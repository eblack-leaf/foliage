Module environment

Expand description

The SDK, and saying what is missing.

Android’s toolchain is normally reached through ANDROID_HOME and ANDROID_NDK_HOME, which means a build depends on how the shell that started it was prepared. Nothing here reads either. The SDK is the path foliage-android.toml names and the NDK is the version it names inside that – so the answer is the same from any shell, and changing it is an edit rather than an export.

The variables are still written, onto the processes this tool starts, because cargo ndk and Gradle read them and there is no other way to tell them. That is the opposite direction: the environment is constructed here rather than consulted. Nothing is exported and nothing outlives the command.
