1//! The files `init` writes.
2//!
3//! Every Gradle and Java file here is a parameterised copy of `rust-mobile/android-activity`'s own
4//! `agdk-mainloop` example -- the crate that implements winit's `android-game-activity` backend --
5//! verified against `androidx.games:games-activity` rather than invented. Only the values that have
6//! to vary per app are placeholders; everything else is copied as it stands.
7//!
8//! Placeholders are `{{NAME}}` and are substituted by [`fill`], rather than the text being built up
9//! by `format!`. A Gradle build file is mostly braces, and the escaping that would take is exactly
10//! the noise that makes a template hard to check against its upstream.
11
12/// Substitutes `{{NAME}}` placeholders.
13fn fill(template: &str, values: &[(&str, &str)]) -> String {
14    let mut out = template.to_string();
15    for (name, value) in values {
16        out = out.replace(&format!("{{{{{name}}}}}"), value);
17    }
18    out
19}

368const README: &str = r#"# {{APP_NAME}} -- Android
369
370Generated by `foliage-android init`, **including this file**. A rerun overwrites everything in this
371directory, so keep notes of your own somewhere else. Settings live in `foliage-android.toml` at the
372repo root -- edit there and rerun `init`, rather than editing these files.
373
374This Gradle project exists because `androidx.games:games-activity` -- Google's `GameActivity`, which
375winit's `android-game-activity` backend targets -- is a Java/Kotlin AAR, and there is no way to link
376one without Gradle. Unavoidable rather than a workaround.
377
378## Building
379
380From the repo root:
381
382```sh
383foliage-android setup    # the SDK, NDK and rust targets, into the `sdk` directory
384foliage-android doctor   # what is installed, and what is not
385foliage-android build    # every configured ABI, then the APK
386foliage-android run      # the above, installed and launched on a connected device
387```
388
389`build` compiles each ABI into `app/src/main/jniLibs/<abi>/` and then assembles. Doing it by hand is
390what the tool exists to avoid: `jniLibs/` is an *input* directory to Gradle rather than an output it
391tracks, so whatever `.so` is sitting there gets packaged. A Rust build that failed, was skipped, or
392wrote somewhere else still assembles successfully -- shipping the *previous* library. The luckier
393outcome is an `UnsatisfiedLinkError` at launch; the unluckier one is old code running quietly.
394
395## SDK levels
396
397Three numbers do three different jobs, and only one gates hardware:
398
399- **`compile-sdk`** -- which API the compiler sees. A build-time download
400  (`platforms/android-{{COMPILE_SDK}}`), with no bearing on what the APK runs on.
401- **`min-sdk`** -- the device gate. Anything below refuses to install the APK.
402- **`target-sdk`** -- which platform behaviours the app opts into. Affects runtime behaviour on
403  newer devices; not an install gate.
404
405Lowering `compile-sdk` does not widen device support -- `min-sdk` is the knob for that. Whichever
406`compile-sdk` is set, install the matching `platforms/android-<n>` or Gradle will not find it.
407
408## Emulator
409
410Useful for exercising API levels you do not own hardware for.
411
412```sh
413android sdk install emulator system-images/android-{{COMPILE_SDK}}/google_apis/{{EMULATOR_ABI}}
414android emulator create --list-profiles      # what you can pick from
415android emulator create medium_phone         # profile is positional, and required
416android emulator start medium_phone
417```
418
419On Linux the emulator needs `/dev/kvm`; `test -r /dev/kvm && test -w /dev/kvm && echo ok` settles
420whether you have it, and `sudo usermod -aG kvm $USER` plus a re-login is the fix. Group membership
421is not the whole story -- some distributions grant access through an ACL -- so test rather than
422reading `groups`.
423
424**Force the GPU, or everything is software-rendered.** New AVDs default to `hw.gpu.mode=auto`, and
425`auto` readily decides against a capable host GPU and falls back to SwiftShader -- CPU rendering,
426sluggish enough that the launcher feels broken, not just your app. Set `hw.gpu.mode=host` in
427`~/.android/avd/<name>.avd/config.ini`. To check which you got:
428`adb shell dumpsys SurfaceFlinger | grep -i gles` names either your real GPU or `SwiftShader`.
429
430**Build the emulator's own ABI.** Current x86_64 system images translate ARM binaries, so an
431`arm64-v8a`-only APK does run on an x86_64 emulator -- routed through `libndk_translation.so`, slow
432enough to make frame timings meaningless and to trip ANR dialogs. `init` adds this machine's ABI to
433`foliage-android.toml` for that reason; both live in `jniLibs/` at once and Android prefers a native
434ABI over a translated one, so one APK serves emulator and phone.
435
436AVDs live in `~/.android/avd/`, **not** in the SDK directory -- deleting the SDK leaves them behind.
437
438## Release signing
439
440`foliage-android build` needs nothing extra: AGP generates and uses a debug keystore.
441`--release` also runs without one, but produces an **unsigned** APK no device will install. For a
442real signed release:
443
4441. Generate a keystore once. Keep the file and passwords somewhere safe outside the repo -- losing
445   this keystore means never shipping an update to the same `applicationId` under the same identity
446   again.
447
448   ```sh
449   keytool -genkeypair -v -keystore ~/keys/{{LIB_NAME}}-release.keystore \
450     -alias {{LIB_NAME}} -keyalg RSA -keysize 2048 -validity 10000
451   ```
452
4532. Create `{{PROJECT}}/keystore.properties`, and gitignore it:
454
455   ```properties
456   storeFile=/home/you/keys/{{LIB_NAME}}-release.keystore
457   storePassword=<the password you set above>
458   keyAlias={{LIB_NAME}}
459   keyPassword=<same password, unless you set a separate key password>
460   ```
461
4623. That is all -- `app/build.gradle` reads that file whenever it is present.

464## Troubleshooting
465
466- **App installs but crashes immediately.** Clear the log, launch, and read the abort message:
467
468  ```sh
469  adb logcat -c
470  adb shell am start -n {{APP_NAME}}/.MainActivity
471  adb logcat -d | grep -B5 -A40 "Fatal signal"
472  ```
473
474  The tombstone's `Abort message:` line names the cause. `System.loadLibrary` failing means
475  `jniLibs/` has nothing for the device's ABI -- add it to `abis` in `foliage-android.toml`.
476- **`RegisterNatives failed` / `NoSuchMethodError` on a GameActivity method.** The AAR and the
477  GameActivity C++ compiled into the library are different versions. `foliage-android doctor`
478  compares the two and names the mismatch. This aborts before any Rust runs, so it is not a bug in
479  your app. Prefer `cargo update -p android-activity` over pinning an older AAR: matching them at
480  the older version also stops the crash, but a GameActivity years behind the running platform can
481  deliver no touch input at all -- the app launches, draws correctly, and ignores every tap, with
482  nothing in the log.
483- **Gradle disagrees about where the SDK is.** Check `local.properties`, which Gradle writes with
484  the path it resolved, against what `foliage-android doctor` reports. Nothing in this toolchain
485  reads `ANDROID_HOME`: the SDK is the `sdk` path in `foliage-android.toml` and nowhere else, and
486  the variables Gradle and `cargo ndk` need are set on those processes rather than in your shell.
487- **A download died partway.** `setup` installs one package at a time and retries each, so what
488  already arrived is kept -- rerun it and it resumes rather than starting over.
489
490## Getting the APK onto a phone
491
492`foliage-android run` uses `adb`, which needs USB debugging. Without it, transfer the APK however
493you like -- USB copy, email, syncthing. The phone will refuse to install it until you allow it:
494whatever app opens the APK prompts "Install unknown apps" the first time.
