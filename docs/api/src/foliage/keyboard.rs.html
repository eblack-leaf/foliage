1//! The soft keyboard -- raised by focus, and by nothing else.
2//!
3//! A phone has no keyboard until something asks for one, and the thing that asks is a field holding
4//! focus. That is the whole rule, and it needs no declaration of its own: focus already rests only
5//! on what said [`interactive`](crate::Place::interactive), and a [`TextInput`](crate::TextInput)
6//! is the only thing in the engine that is typed *into*. So the keyboard is raised for the field
7//! that holds focus and lowered for everything else, decided in the same breath as the caret's
8//! visibility and from the same state.
9//!
10//! What a field may say is which **[`Keypad`]** it wants, because a telephone number behind a full
11//! alphabet is the one thing the platform cannot be left to guess.
12//!
13//! # The web owns the keyboard, so the web owns the keys
14//!
15//! There is no way to raise a browser's keyboard except by giving DOM focus to a real input, and
16//! doing that takes keyboard focus off the canvas winit is listening on -- so every key typed after
17//! it would be swallowed by an input the person cannot see. The hidden input therefore hands them
18//! back: what it composes arrives as text and what it does not is read from the key itself, both
19//! entering [`Incoming`](crate::interaction::input::Incoming) exactly where a translated winit
20//! event enters it.
21//!
22//! # Android types into the activity's own text, and the engine reads it back
23//!
24//! The other platform with a keyboard of its own. The activity raises and lowers it directly, so
25//! there is no hidden element to hold -- only the activity handle, which is the one thing the engine
26//! cannot reach for itself.
27//!
28//! What is typed on it does not come back as key events. A soft keyboard types through the input
29//! method, into the text state the activity keeps for it -- a word composed and recomposed, a
30//! correction made over it -- and winit 0.30's Android backend takes the word that the state moved
31//! and drops it rather than reporting it. The state itself is still there to read, so the engine
32//! reads it after every pass of the loop and types in what changed as keystrokes: what was taken
33//! back as backspaces, what was put in as characters, the way the web's hidden input hands back
34//! what it composed. See [`edited`].
35//!
36//! The state is a window onto the field and not the field's value: it is emptied whenever a field
37//! is given the keyboard, so it holds what was typed since, and the caret stands in the field where
38//! it stands in the state. A key the input method sends as a key -- a backspace with nothing in the
39//! state to take it from, anything typed on a hardware keyboard -- arrives as an ordinary key event
40//! and is typed as one.
41//!
42//! # A desktop's input method composes into the window
43//!
44//! A desktop has no keyboard to raise, but it may have an input method: what turns keys into a word
45//! of Japanese, or a dead key and a letter into one accented letter. The window allows one only
46//! while a field that takes typing holds focus, and what it commits arrives as text and is typed in
47//! a character at a time, the way the web's hidden input hands back what it composed. A key the
48//! method does not take arrives as itself, and one it does is the method's -- so nothing arrives
49//! twice. A masked field allows none: a method composes what it is shown, and one that predicts
50//! would learn the passphrase.
51//!
52//! Nothing is raised anywhere else, because nothing else has one.
53

59/// Which keys a soft keyboard offers.
60///
61/// A hint and not a constraint: it changes what is easy to type and never what a field accepts, so
62/// a [`Keypad::Number`] field can still be pasted a word into and is still the app's to validate.
63/// Ignored where the platform has no keyboard of its own to raise.
64#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
65pub enum Keypad {
66    /// Letters. What a field asks for unless it says otherwise.
67    #[default]
68    Text,
69    /// Digits, for a quantity or a code.
70    Number,
71    /// A dialling pad.
72    Telephone,
73}
74
75impl Keypad {
76    /// What the browser is told to offer, as `inputmode` names it.
77    #[cfg_attr(not(target_family = "wasm"), allow(dead_code))]
78    fn mode(self) -> &'static str {
79        match self {
80            Self::Text => "text",
81            Self::Number => "numeric",
82            Self::Telephone => "tel",
83        }
84    }
85
86    /// What Android is told to offer, as `EditorInfo.inputType` names it.
87    ///
88    /// The class only. A variation would say what *kind* of text -- an address, a password, a URI --
89    /// which is a distinction this engine does not make and one the field itself would have to
90    /// declare.
91    #[cfg(target_os = "android")]
92    fn class(self) -> winit::platform::android::activity::input::InputType {
93        use winit::platform::android::activity::input::InputType;
94
95        match self {
96            Self::Text => InputType::TYPE_CLASS_TEXT,
97            Self::Number => InputType::TYPE_CLASS_NUMBER,
98            Self::Telephone => InputType::TYPE_CLASS_PHONE,
99        }
100    }
101}

103/// The soft keyboard, and what it is currently showing.
104///
105/// What is raised is engine state on every target, and raising it is the platform's -- so the rule
106/// that focus decides the keyboard is proven headlessly while the DOM half stays the edge the suite
107/// cannot reach, exactly as the winit translation is.
108#[derive(Default)]
109pub(crate) struct Keyboard {
110    /// What is up, if anything is. Kept so the platform is asked only when the answer changes.
111    raised: Option<Keypad>,
112    /// Whether an input method may compose into the window, which is what the window was last told.
113    composing: bool,
114    /// The window an input method composes into. Absent until [`window`](Keyboard::window), and
115    /// absent for good under the headless suite.
116    #[cfg(not(any(target_family = "wasm", target_os = "android", target_os = "ios")))]
117    window: Option<Arc<winit::window::Window>>,
118    /// The hidden input the browser raises its keyboard for. Absent until
119    /// [`attach`](Keyboard::attach), and absent for good under the headless suite.
120    #[cfg(target_family = "wasm")]
121    trigger: Option<web::Trigger>,
122    /// The activity Android raises its keyboard through. Absent until
123    /// [`activity`](Keyboard::activity), and absent for good under the headless suite.
124    #[cfg(target_os = "android")]
125    activity: Option<winit::platform::android::activity::AndroidApp>,
126    /// The field typing goes into, so the input method's state is emptied when it moves.
127    field: Option<crate::leaf::Leaf>,
128    /// What the input method's state held when it was last read, or none while nothing is raised.
129    #[cfg(target_os = "android")]
130    held: Option<Held>,
131}

184    /// Raises the keyboard `wanted` asks for, or lowers whatever is up, and lets an input method
185    /// compose into the window where `composing` says it may.
186    ///
187    /// Called every frame with the whole answer rather than told about changes, because the answer
188    /// is a product of focus and is recomputed like every other product.
189    ///
190    /// What is *up* is compared, so the mode is written and the trace is made only where it moved.
191    /// DOM focus is taken on the same change, and again after any press has ended: the page can
192    /// take focus off the hidden input without the engine hearing about it -- a press on the canvas
193    /// does exactly that, and is how every tap from one field to another arrives -- so a press is
194    /// what it is given back after. After, and not during: see `web::Trigger::build`.
195    ///
196    /// And only then. A browser takes focus off the input for reasons of its own as well -- a
197    /// phone's enter key, a back gesture, the keyboard's own dismiss -- and each of those is the
198    /// person putting the keyboard away. Taken back on every frame, the keyboard comes straight up
199    /// again, the viewport resizes under it, the resize is a frame, the frame takes focus back,
200    /// and the page and the engine trade the keyboard back and forth for as long as there are
201    /// frames to trade it on. Left down, it stays down until the field is pressed again.
202    ///
203    /// `field` is what typing goes into. On Android a field given the keyboard starts the input
204    /// method over, so nothing composed for one field is recomposed into the next.
205    pub(crate) fn raise(
206        &mut self,
207        field: Option<crate::leaf::Leaf>,
208        wanted: Option<Keypad>,
209        composing: bool,
210    ) {
211        let moved = wanted != self.raised;
212        if moved {
213            self.raised = wanted;
214            debug!(keypad = ?wanted, "keyboard");
215        }
216        let switched = composing != self.composing;
217        #[cfg_attr(not(target_os = "android"), allow(unused_variables))]
218        let entered = field != self.field;
219        self.field = field;
220        if switched {
221            self.composing = composing;
222            debug!(composing, "input method");
223            // A desktop's alone. The web composes into its hidden input and Android into its
224            // activity, and both of those are raised below; on either, as on iOS, allowing an input
225            // method is raising a keyboard, which is not this question.
226            #[cfg(not(any(target_family = "wasm", target_os = "android", target_os = "ios")))]
227            if let Some(window) = &self.window {
228                window.set_ime_allowed(composing);
229            }
230        }
231        #[cfg(target_family = "wasm")]
232        if let Some(trigger) = &self.trigger {
233            // Taken whatever is wanted, so a press made with no field focused is not still waiting
234            // to be answered the next time one is.
235            let pressed = trigger.pressed();
236            match wanted {
237                Some(keypad) => {
238                    if moved {
239                        trigger.mode(keypad);
240                    }
241                    if moved || pressed {
242                        trigger.focus();
243                    }
244                }
245                None if moved => trigger.blur(),
246                None => {}
247            }
248        }
249        // Only where it moved, unlike the web: there is no element here whose focus the platform can
250        // take away behind the engine's back, so what was raised stays raised until this lowers it.
251        #[cfg(target_os = "android")]
252        if let Some(activity) = &self.activity {
253            use winit::platform::android::activity::input::{
254                ImeOptions, InputType, TextInputAction, TextInputState, TextSpan,
255            };
256
257            match wanted {
258                Some(keypad) => {
259                    // Written before the keyboard is raised. An input type given to one already up
260                    // changes nothing a person can see until it has been dismissed and raised again.
261                    if moved || switched {
262                        // A field that composes nothing is a masked one, and a password is what
263                        // tells the input method to neither show suggestions nor learn from it.
264                        let class = match (composing, keypad) {
265                            (true, _) => keypad.class(),
266                            (false, Keypad::Text) => {
267                                InputType::TYPE_CLASS_TEXT | InputType::TYPE_TEXT_VARIATION_PASSWORD
268                            }
269                            (false, _) => {
270                                keypad.class() | InputType::TYPE_NUMBER_VARIATION_PASSWORD
271                            }
272                        };
273                        // No action on the enter key, so it is sent as a key or typed as a line
274                        // break, both of which arrive. An action is reported as an editor action,
275                        // which winit takes and drops like the text. What the key then does is the
276                        // field's -- `submitted` is reported for it whatever it is labelled. And
277                        // never the whole screen: a field is drawn where it stands, and an input
278                        // method's own copy of it would be a second one.
279                        let mut options = ImeOptions::IME_FLAG_NO_ENTER_ACTION
280                            | ImeOptions::IME_FLAG_NO_FULLSCREEN;
281                        if !composing {
282                            options |= ImeOptions::IME_FLAG_NO_PERSONALIZED_LEARNING;
283                        }
284                        activity.set_ime_editor_info(class, TextInputAction::Unspecified, options);
285                    }
286                    // Emptied for a field newly given the keyboard, so the state is a window onto
287                    // what is typed into this one from here.
288                    if moved || entered {
289                        activity.set_text_input_state(TextInputState {
290                            text: String::new(),
291                            selection: TextSpan { start: 0, end: 0 },
292                            compose_region: None,
293                        });
294                        self.held = Some(Held::default());
295                    }
296                    // Implicit: focus asked for this keyboard, not a person reaching for one. The
297                    // distinction is the platform's to act on -- an implicit keyboard is the one a
298                    // back gesture is allowed to dismiss.
299                    if moved {
300                        activity.show_soft_input(true);
301                    }
302                }
303                // Everything, not only what was raised implicitly. Focus has left the field, so
304                // there is nothing left for a keyboard to type into either way.
305                None if moved => {
306                    activity.hide_soft_input(false);
307                    self.held = None;
308                }
309                None => {}
310            }
311        }
312    }

314    /// What the input method typed into the activity's text since it was last read, as keys.
315    ///
316    /// Read after every pass of the loop rather than when told, because winit takes the word that
317    /// the state moved and reports nothing. Empty while nothing is raised, and everywhere but
318    /// Android.
319    #[cfg(target_os = "android")]
320    pub(crate) fn typed(&mut self) -> Vec<crate::interaction::input::Key> {
321        let (Some(activity), Some(before)) = (&self.activity, &self.held) else {
322            return Vec::new();
323        };
324        let state = activity.text_input_state();
325        let after = Held {
326            caret: characters(&state.text, state.selection.end),
327            text: state.text,
328        };
329        if after == *before {
330            return Vec::new();
331        }
332        let keys = edited(before, &after);
333        debug!(text = %after.text, caret = after.caret, keys = keys.len(), "input method");
334        self.held = Some(after);
335        keys
336    }

339    ///
340    /// Empty everywhere but the web, and empty there until something has been typed into a keyboard

343        #[cfg(target_family = "wasm")]
344        if let Some(trigger) = &self.trigger {
345            return trigger.captured();
346        }
347        Vec::new()
348    }

351/// What an input method's text held: its words, and where its caret stood among them, in characters.
352#[derive(Clone, Debug, Default, PartialEq, Eq)]
353pub(crate) struct Held {
354    pub(crate) text: String,
355    pub(crate) caret: usize,
356}
357
358/// How many characters `text` holds before `units` of Java's UTF-16, which is what the activity
359/// counts its caret in.
360#[cfg_attr(not(target_os = "android"), allow(dead_code))]
361pub(crate) fn characters(text: &str, units: usize) -> usize {
362    let mut counted = 0;
363    text.chars()
364        .take_while(|character| {
365            counted += character.len_utf16();
366            counted <= units
367        })
368        .count()
369}

371/// The keys that take a field from what an input method held `before` to what it holds `after`,
372/// with the field's caret standing where `before`'s did.
373///
374/// What changed is the run between what the two share at the start and at the end -- a letter put
375/// on a word being composed, a word put over a misspelling, a letter taken off. The caret is taken
376/// to the end of that run, it is taken back a character at a time, what replaced it is typed, and
377/// the caret is taken to where `after`'s stands. A caret that only moved is the last step alone.
378/// A line break typed is the enter key.
379#[cfg_attr(not(target_os = "android"), allow(dead_code))]
380pub(crate) fn edited(before: &Held, after: &Held) -> Vec<crate::interaction::input::Key> {
381    use crate::interaction::input::Key;
382
383    let old: Vec<char> = before.text.chars().collect();
384    let new: Vec<char> = after.text.chars().collect();
385    let shared = old.iter().zip(&new).take_while(|(a, b)| a == b).count();
386    let ending = old[shared..]
387        .iter()
388        .rev()
389        .zip(new[shared..].iter().rev())
390        .take_while(|(a, b)| a == b)
391        .count();
392    let mut keys = Vec::new();
393    let mut caret = before.caret.min(old.len());
394    let step = |keys: &mut Vec<Key>, from: usize, to: usize| {
395        let key = match to > from {
396            true => Key::Right,
397            false => Key::Left,
398        };
399        keys.extend(std::iter::repeat_n(key, from.abs_diff(to)));
400    };
401    let removed = old.len() - ending - shared;
402    let added = &new[shared..new.len() - ending];
403    if removed > 0 || !added.is_empty() {
404        step(&mut keys, caret, old.len() - ending);
405        keys.extend(std::iter::repeat_n(Key::Backspace, removed));
406        // A line break is the enter key, which an input method may type rather than send. Any
407        // other control character is dropped under the rule `photosynthesize` reads a key by.
408        keys.extend(added.iter().filter_map(|&character| match character {
409            '\n' => Some(Key::Enter),
410            character if character.is_control() => None,
411            character => Some(Key::Typed(character)),
412        }));
413        caret = new.len() - ending;
414    }
415    step(&mut keys, caret, after.caret.min(new.len()));
416    keys
417}

419/// The browser's half: one hidden input, and the keys it takes from the canvas given back.
420#[cfg(target_family = "wasm")]
421mod web {
422    use std::cell::{Cell, RefCell};
423    use std::rc::Rc;
424
425    use wasm_bindgen::JsCast;
426    use wasm_bindgen::closure::Closure;
427
428    use super::Keypad;
429    use crate::interaction::input::{Input, Key, Modifiers};

432    /// The id the hidden input is found by. One element rather than one per [`Keypad`]: the pad is
433    /// `inputmode`, which is written before focus moves, so there is nothing three elements would
434    /// say that one cannot.
435    const TRIGGER: &str = "foliage-keypad";
436
437    /// Off screen rather than `display:none`, because an element that is not laid out cannot take
438    /// focus and an element that cannot take focus raises no keyboard. Everything that would let it
439    /// second-guess what is typed is off: the value is read and cleared on every event, so an
440    /// autocorrection would be applied to a value the person never sees.
441    const STYLE: &str = "position:absolute;left:-1px;top:-1px;width:0;height:0;\
442        min-width:0;min-height:0;padding:0;border:0;opacity:0";
443
444    /// What the hidden input has captured and no frame has taken yet.
445    ///
446    /// The browser is single-threaded, so an `Rc` is the whole of what sharing this with the DOM's
447    /// own callbacks needs.
448    #[derive(Clone, Default)]
449    struct Captured(Rc<RefCell<Vec<Input>>>);
450
451    /// The hidden input, what it has taken, and whether the page has been pressed since the engine
452    /// last asked.
453    pub(super) struct Trigger {
454        element: web_sys::HtmlInputElement,
455        captured: Captured,
456        pressed: Rc<Cell<bool>>,
457    }
458
459    impl Trigger {
460        /// Puts the input in the page and wires it to the input stream.
461        ///
462        /// `None` where there is no document to put it in, which is every host that is not a
463        /// browser -- the same absence the headless suite has, reached a different way.
464        pub(super) fn build(wake: Wake) -> Option<Self> {
465            let document = web_sys::window()?.document()?;
466            let element = document
467                .create_element("input")
468                .ok()?
469                .dyn_into::<web_sys::HtmlInputElement>()
470                .ok()?;
471            element.set_id(TRIGGER);
472            element.set_type("text");
473            for (name, value) in [
474                ("style", STYLE),
475                ("autocapitalize", "off"),
476                ("autocomplete", "off"),
477                ("autocorrect", "off"),
478                ("spellcheck", "false"),
479                ("aria-hidden", "true"),
480            ] {
481                element.set_attribute(name, value).ok()?;
482            }
483            document.body()?.append_child(&element).ok()?;
484            let captured = Captured::default();
485            listen(&element, &captured, &wake);
486            let pressed = Rc::new(Cell::new(false));
487            // On the document and while capturing, so it is heard whatever the press lands on.
488            // Nothing is taken from the press: it goes on to the canvas, and to winit, as it would
489            // have.
490            //
491            // Noted when the press *ends*, never when it begins. Winit focuses the canvas on
492            // `pointerdown`, so taking focus back is the canvas blurring -- which winit reports as
493            // the window losing focus, and a window losing focus cancels whatever press is held. A
494            // focus given back mid-press is every tap made while a field holds focus arriving as a
495            // cancel: nothing on the page can be pressed until focus leaves the field some other
496            // way.
497            {
498                let pressed = pressed.clone();
499                let noted = Closure::wrap(Box::new(move |_: web_sys::Event| {
500                    pressed.set(true);
501                }) as Box<dyn FnMut(_)>);
502                for name in ["pointerup", "pointercancel"] {
503                    let _ = document.add_event_listener_with_callback_and_bool(
504                        name,
505                        noted.as_ref().unchecked_ref(),
506                        true,
507                    );
508                }
509                // For the life of the program, as the input's own listeners are.
510                noted.forget();
511            }
512            Some(Self {
513                element,
514                captured,
515                pressed,
516            })
517        }
518
519        /// Says which keys to offer, before anything is offered.
520        ///
521        /// A mode written to an input that already holds focus changes nothing the person can see
522        /// until the keyboard has been dismissed and raised again, so this is only ever written
523        /// while the keyboard is down.
524        pub(super) fn mode(&self, keypad: Keypad) {
525            let _ = self.element.set_attribute("inputmode", keypad.mode());
526        }
527
528        /// Gives the input DOM focus, which is the only thing a browser raises a keyboard for.
529        pub(super) fn focus(&self) {
530            let _ = self.element.focus();
531        }
532
533        pub(super) fn blur(&self) {
534            let _ = self.element.blur();
535        }
536
537        /// Whether a press on the page has ended since this was last asked, which is the one way focus
538        /// leaves the input that the engine takes it back after.
539        pub(super) fn pressed(&self) -> bool {
540            self.pressed.replace(false)
541        }
542
543        pub(super) fn captured(&self) -> Vec<Input> {
544            core::mem::take(&mut *self.captured.0.borrow_mut())
545        }
546    }

548    /// Wires the three events a hidden input has to give back.
549    ///
550    /// `input` is what was composed -- a plain letter, a dead-key sequence, a whole word an IME
551    /// committed -- and is the only one that answers for text, because the browser is what resolved
552    /// the layout. `keydown` is for the keys that produce no text and would otherwise be spent on
553    /// the input's own editing, and for a character held with a modifier, which produces no `input`
554    /// event because it is a command rather than something to insert. `paste` carries what another
555    /// program put on the clipboard, which is the only way this target ever sees it.
556    fn listen(element: &web_sys::HtmlInputElement, captured: &Captured, wake: &Wake) {
557        let composed = {
558            let (captured, wake) = (captured.clone(), wake.clone());
559            Closure::wrap(Box::new(move |event: web_sys::Event| {
560                let Some(input) = event
561                    .target()
562                    .and_then(|target| target.dyn_into::<web_sys::HtmlInputElement>().ok())
563                else {
564                    return;
565                };
566                let value = input.value();
567                if value.is_empty() {
568                    return;
569                }
570                // Cleared at once. What was typed is carried as keystrokes from here on, and a
571                // value left in the input would be composed against by whatever is typed next.
572                input.set_value("");
573                captured.push(
574                    value
575                        .chars()
576                        // The rule `photosynthesize` reads a winit key by: a control character is
577                        // what a key that means something produces where the platform hands text
578                        // as well, and inserting one would put it in the value.
579                        .filter(|character| !character.is_control())
580                        .map(|character| Input::Keyed(Key::Typed(character)))
581                        .collect(),
582                );
583                wake.rouse();
584            }) as Box<dyn FnMut(_)>)
585        };
586        let pressed = {
587            let (captured, wake) = (captured.clone(), wake.clone());
588            Closure::wrap(Box::new(move |event: web_sys::KeyboardEvent| {
589                // Read from this event rather than from what the engine last heard: the canvas
590                // stopped receiving `ModifiersChanged` the moment this input took focus, so the
591                // engine's own tracker is exactly as starved as the key events are.
592                let modifiers = Modifiers {
593                    shift: event.shift_key(),
594                    control: event.ctrl_key() || event.meta_key(),
595                };
596                let Some(key) = named(&event.key(), modifiers) else {
597                    return;
598                };
599                // The input's own editing would otherwise spend the key -- a backspace deleting
600                // from a value that is always empty, an arrow moving a caret nobody can see.
601                event.prevent_default();
602                captured.push(vec![
603                    Input::Modifiers(modifiers),
604                    Input::Keyed(key),
605                    Input::Modifiers(Modifiers::default()),
606                ]);
607                wake.rouse();
608            }) as Box<dyn FnMut(_)>)
609        };
610        let pasted = {
611            let (captured, wake) = (captured.clone(), wake.clone());
612            Closure::wrap(Box::new(move |event: web_sys::ClipboardEvent| {
613                // Empty for a paste that is not text -- a picture, a file -- which the browser
614                // fires this for all the same. Nothing was pasted as far as this engine is
615                // concerned, and letting it through would be an edit that wrote nothing.
616                let Some(text) = event
617                    .clipboard_data()
618                    .and_then(|data| data.get_data("text/plain").ok())
619                    .filter(|text| !text.is_empty())
620                else {
621                    return;
622                };
623                // The value is where the browser would put this, and the `input` event that
624                // followed would then insert it a character at a time as if it had been typed.
625                event.prevent_default();
626                captured.push(vec![Input::Pasted(text)]);
627                wake.rouse();
628            }) as Box<dyn FnMut(_)>)
629        };
630        for (name, callback) in [
631            ("input", composed.as_ref()),
632            ("keydown", pressed.as_ref()),
633            ("paste", pasted.as_ref()),
634        ] {
635            let _ = element.add_event_listener_with_callback(name, callback.unchecked_ref());
636        }
637        // The listeners outlive this call by exactly as long as the input does, which is the life
638        // of the program: there is one hidden input and nothing ever takes it out of the page.
639        composed.forget();
640        pressed.forget();
641        pasted.forget();
642    }
643
644    /// Which engine key a browser's `KeyboardEvent.key` is, where it is one this path has to carry.
645    ///
646    /// Mirrors `photosynthesize`'s reading of a winit key, and for the same reason: a key that
647    /// produced text is left to the `input` event that carries it, so the two paths do not both
648    /// answer for the same press. `Ctrl+V` is the same rule reaching the third listener --
649    /// answering it here would take the key, and taking the key is what stops the browser ever
650    /// firing the `paste` that carries the text.
651    ///
652    /// Nothing is lost at the root by declining it: this listener hears a key only while the hidden
653    /// input holds DOM focus, which is only ever while a field holds the engine's, and a chord
654    /// pressed with focus nowhere reaches the canvas through winit like every other key.
655    fn named(key: &str, modifiers: Modifiers) -> Option<Key> {
656        // A browser reports the letter of a chord in the case the shift key put it in.
657        if modifiers.control && key.eq_ignore_ascii_case("v") {
658            return None;
659        }
660        let named = match key {
661            "Backspace" => Key::Backspace,
662            "Delete" => Key::Delete,
663            "ArrowLeft" => Key::Left,
664            "ArrowRight" => Key::Right,
665            "ArrowUp" => Key::Up,
666            "ArrowDown" => Key::Down,
667            "Home" => Key::Home,
668            "End" => Key::End,
669            "Enter" => Key::Enter,
670            "Tab" => Key::Tab,
671            "Escape" => Key::Escape,
672            // A character held with control is a command and produces no `input` event, so this is
673            // the only path it has. A character held with nothing is text and already has one.
674            _ => {
675                let mut characters = key.chars();
676                let character = characters.next()?;
677                if characters.next().is_some() || !modifiers.control {
678                    return None;
679                }
680                Key::Typed(character)
681            }
682        };
683        Some(named)
684    }

686    impl Captured {
687        fn push(&self, inputs: Vec<Input>) {
688            self.0.borrow_mut().extend(inputs);
689        }
690    }
