1//! Aspen -- animation.
2//!
3//! # A tween resolves both of its endpoints every frame
4//!
5//! Animating a placement is the hard case, and it is the one the rest of the engine was shaped
6//! around. A [`Location`] is not a value: it is a function from context to a box, and the context
7//! -- the breakpoint, the trunk's geometry, an anchor's box, a measured extent -- can change while
8//! a motion is running. So "animate to this placement" cannot be answered once at the start.
9//!
10//! ```text
11//! box(t) = blend( resolve(from, context now), resolve(to, context now), ease(t) )
12//! ```
13//!
14//! Both endpoints re-resolve every frame, which is why the resolver is a pure function
15//! ([`placement::resolve`](crate::placement::resolve)) callable more than once per element per
16//! frame. Nothing is cached, so nothing can go stale: a resize, a crossed breakpoint, a moved
17//! anchor or a repaint all reach both ends of the motion at once, and it lands exactly on target
18//! rather than near it.
19//!
20//! # Where the target lives
21//!
22//! Starting a motion writes the target to the element **immediately**, and the motion carries what
23//! the element left. Two properties fall out of that and neither has any code:
24//!
25//! - **Ending changes nothing.** The blend at `t = 1` already equals the plain resolution, so there
26//!   is no settling step that could land a pixel off.
27//! - **Cancelling is a removal.** A direct write replaces the declaration and drops the motion
28//!   (F8); the element is at what was written, and there is no stale state to reconcile.
29//! - **Ending early is the same ending.** [`stop`](crate::Grow::stop) and
30//!   [`finish`](crate::Grow::finish) give up the duration and not the destination, so an interrupted
31//!   motion leaves the element exactly where running it out would have. Nothing writes back a blend
32//!   from part way along: an intermediate is a synthesized value the app never declared, and a
33//!   declaration made of one would be deaf to everything both endpoints re-resolve against. An
34//!   element that is to stop somewhere else stops there by being written there, which is the case
35//!   above.
36//!
37//! # Progress and application are separate
38//!
39//! This phase advances every live tween against the one clock (F6) and computes its eased progress.
40//! Applying that progress belongs to whichever phase owns the property, and which phase that is
41//! follows from one line:
42//!
43//! > **A blend of the same type as the declaration is written back over it here. A blend of a
44//! > different type is left to the phase that reads the declaration.**
45//!
46//! | Property | Blends to | Applied in |
47//! |---|---|---|
48//! | [`Motion::Opacity`] | a number, like its declaration | `animate` -- written back |
49//! | [`Motion::Location`] | a box, where the declaration is a placement | `resolve` |
50//! | [`Motion::Color`], [`Motion::Palette`] | a color, where the declaration is a [`Fill`] | `extract` |
51//! | [`Motion::Polygon`] | a shape, like its declaration | `animate` -- written back |
52//! | [`Motion::Scroll`] | an offset, where the target is a [`ScrollTo`] | `resolve`, at R4 |
53//!
54//! The fill case is the one that needs saying. A [`Fill`] is a role *or* a color, and a blend of two
55//! of them is always a color -- so even two literals cannot be written back, and the blend belongs
56//! where a fill becomes a color. That is extraction, for the same reason it is already where an
57//! element's opacity is taken into its fill: nothing then holds a second color for a repaint to
58//! have to find.
59//!
60//! # One writer per property
61//!
62//! There is at most one motion per property per element, so two motions are never blending the same
63//! declaration. A second one on a property already moving **replaces** it, starting from a snapshot
64//! of where the element is rather than from where the first motion began -- otherwise the element
65//! would jump back to the old start. The drain runs before this phase and cancels the motion on any
66//! property it writes, so nothing reaches its applying phase with both a pending write and a
67//! running tween.

88/// One running tween, as the app names it: a motion, a scalar channel, or a timer.
89///
90/// Handed out by [`animate`](crate::Grow::animate), [`tween`](crate::Grow::tween) and
91/// [`timer`](crate::Grow::timer), and what [`Pollen`](crate::Pollen) is asked about. Opaque: there is
92/// nothing to be done with one but read how far it has come, hear that it ended, and stop it.
93#[derive(Copy, Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Debug)]
94pub struct Tween(pub(crate) u64);
95
96/// A group of running tweens, reported when the last of them ends.
97///
98/// Handed out by [`sequence`](crate::Grow::sequence) and joined with
99/// [`Timing::within`] -- from anywhere, at any frame, by anything that runs on the clock. A group is
100/// a *name*, not a call: the whole point of one is timing things together that have no reason to be
101/// written together, so nothing about it requires the members to be stated in one place.
102///
103/// It is over when nothing is running under it any more, however each member ended -- landed,
104/// stopped, cancelled by a direct write, or taken down with its element. There is no second report
105/// for the ways a group can stop being busy, because a group being over is one fact.
106///
107/// A name and a count, with no reach over what joined it: stopping one member is nothing to the
108/// others, and there is no list of them for it to be anything to. Members join from any callsite at
109/// any frame, so a group never owned them -- it only ever knew how many were running.
110#[derive(Copy, Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Debug)]
111pub struct Sequence(pub(crate) u64);

113/// What can be animated.
114///
115/// A property belongs here if animating it is a normal thing to want, or if it **cannot be animated
116/// from outside** because it needs context only the engine has. [`Location`](Motion::Location),
117/// [`Palette`](Motion::Palette) and [`Scroll`](Motion::Scroll) are the second kind: nothing outside
118/// can resolve a placement against a breakpoint and an anchor, a role against the scheme in force,
119/// or a destination against an extent the frame has yet to measure.
120///
121/// The list is closed because the engine's obligations should be, not because an app's are.
122/// Everything else -- a font size, a count of sides, a value foliage has no concept of -- is a
123/// [`tween`](crate::Grow::tween), which hands out the clock and the easing and writes nothing.
124#[derive(Clone, Debug, PartialEq)]
125#[non_exhaustive]
126pub enum Motion {
127    /// How opaque the element is, multiplied through everything grown under it. Fully transparent
128    /// is not there: an element that arrives at zero leaves the box stack.
129    Opacity(f32),
130    /// The color the element is filled with, stated outright. The ordinary case, and the one that
131    /// needs no scheme to mean anything.
132    ///
133    /// Dropped, like any op naming something it does not apply to, if the element draws nothing.
134    Color(Color),
135    /// The [`Palette`] role the element is filled with, for a fill that is part of the scheme.
136    ///
137    /// What a role resolves to is the [`Scheme`](crate::Scheme)'s answer, taken every frame for
138    /// whichever ends are roles -- so a repaint mid-motion moves the motion. The two share one
139    /// property: a fill can only be going to one place, and a write to it cancels either.
140    Palette(Palette),
141    /// Where the element sits. Both endpoints re-resolve every frame in the same context, so the
142    /// motion stays correct through anything that moves either of them.
143    Location(Location),
144    /// Where a scrolling region is moved to.
145    ///
146    /// The other kind that cannot be animated from outside: nothing outside can answer
147    /// [`ScrollTo::end`] against an extent the frame has yet to measure. The destination
148    /// re-resolves every frame like a placement does, so a motion toward the end of a list that
149    /// grows under it still lands on the end.
150    ///
151    /// A drag is a write, so a reader taking hold of the region cancels it (F8). The person wins.
152    ///
153    /// Dropped, like any op naming something it does not apply to, if the element does not scroll
154    /// or the destination leaves no axis to move.
155    Scroll(ScrollTo),
156    /// What a regular polygon looks like: how many sides, how round its corners, how far it is
157    /// turned. Three numbers, so it interpolates plainly and needs none of the machinery a
158    /// placement's endpoints do -- a fractional side count is a shape between two whole ones, which
159    /// is what makes a hexagon become a triangle by passing through the shapes between them.
160    ///
161    /// Dropped, like any op naming something it does not apply to, if the element is not a
162    /// [`Polygon`](crate::Polygon).
163    Polygon(Shape),
164}

166/// Which declared property a motion is moving.
167///
168/// The key one is stored under, so starting a second motion on a property replaces the first and a
169/// write to that property cancels it -- both by naming the same slot. It is the *property* and not
170/// the kind of value stated about it: two ways to say where a fill is going are two `Motion`
171/// variants sharing this one slot, and a write to the fill cancels either.
172#[derive(Copy, Clone, PartialEq, Eq, Hash, Debug)]
173pub(crate) enum Property {
174    Location,
175    Opacity,
176    Fill,
177    Scroll,
178    Shape,
179}
180
181impl Property {
182    /// Every property a motion can be running on, which is what an element being taken down has to
183    /// be cleared from.
184    const ALL: [Property; 5] = [
185        Property::Location,
186        Property::Opacity,
187        Property::Fill,
188        Property::Scroll,
189        Property::Shape,
190    ];
191}

193/// Where a motion started from.
194///
195/// A **declared** endpoint is a value the app wrote, so it re-resolves every frame in the current
196/// context and the motion stays correct through anything that changes what it means.
197///
198/// A **snapshot** is what a retarget takes, and that is right rather than a compromise: a mid-motion
199/// blend is a synthesized intermediate that never corresponded to any declared state, so there is
200/// nothing for it to be stale relative to. It is a starting pixel, and a starting pixel is all it
201/// needs to be. The target stays fully responsive, so the landing is exact regardless.
202#[derive(Clone, Debug)]
203pub(crate) enum Departed<D, S> {
204    Declared(D),
205    Snapshot(S),
206}
207
208/// The endpoints a motion carries, which are the ones the element is not already holding.
209#[derive(Clone, Debug)]
210enum Moving {
211    /// The placement the element left. Its target is the element's own [`Location`], written when
212    /// the motion started.
213    Location(Departed<Location, Section>),
214    /// The fill the element left, role or literal alike. Its target is the element's own fill,
215    /// written when the motion started.
216    Fill(Departed<Fill, Color>),
217    /// Both ends, because neither is left on the element: the blend is written back over the
218    /// declaration every frame, so the element holds where the motion has reached and not where it
219    /// began or where it is going.
220    Opacity { from: f32, to: f32 },
221    /// Both ends again, and for the opposite reason: an offset is a *resolved* value rather than a
222    /// declaration, so there is nothing on the element for a target to be written to and nothing
223    /// for a departure to be re-resolved from. What it left is a number of pixels and is carried as
224    /// one; where it is going is a statement about the region and re-resolves every frame.
225    Scroll { from: Position, to: ScrollTo },
226    /// Both ends, for the reason opacity carries both: a shape blends to a shape, so the blend is
227    /// written back over the declaration every frame and the element holds where the motion has
228    /// reached rather than where it began or where it is going.
229    Shape { from: Shape, to: Shape },
230}

232/// How far a tween has come, against the one clock.
233#[derive(Copy, Clone, Debug)]
234struct Progress {
235    elapsed: Duration,
236    timing: Timing,
237    /// The eased progress, taken once when the frame's delta is charged.
238    ///
239    /// Held rather than recomputed on each read, because the phases that apply a blend read it
240    /// again after this one has run -- `resolve` twice, once per axis -- and a shaped ease is a
241    /// curve parameter solved for rather than a multiply. One solve per tween per frame.
242    at: f32,
243    /// Whether a frame's delta has been charged to it yet.
244    ///
245    /// A tween created at the drain begins at this frame's instant, and the delta is how long the
246    /// interval *ending* at that instant took -- time that elapsed before the tween existed.
247    /// Charging it would move the element on the frame it was told to start, away from where it
248    /// currently is.
249    charged: bool,
250}
251
252impl Progress {
253    fn new(timing: Timing) -> Self {
254        Self {
255            elapsed: Duration::ZERO,
256            timing,
257            at: timing.at(Duration::ZERO),
258            charged: false,
259        }
260    }
261
262    /// Takes this frame's delta, and reports the progress it leaves.
263    fn advance(&mut self, delta: Duration) -> f32 {
264        match self.charged {
265            true => self.elapsed += delta,
266            false => self.charged = true,
267        }
268        self.at = self.timing.at(self.elapsed);
269        self.at
270    }
271
272    /// Progress as this frame left it.
273    fn at(&self) -> f32 {
274        self.at
275    }
276
277    fn done(&self) -> bool {
278        self.timing.done(self.elapsed)
279    }
280}

282/// One running motion.
283#[derive(Clone, Debug)]
284struct Motioning {
285    moving: Moving,
286    progress: Progress,
287    /// What it is reported under, and what stops it. Its own rather than the property's: a name is
288    /// never handed out twice, so a motion replaced on a property it shares reports nothing further
289    /// and the name in the app's hand cannot come to mean the motion that replaced it.
290    tween: Tween,
291    /// The group its ending is counted into, if it was counted into one.
292    within: Option<Sequence>,
293}
294
295impl Motioning {
296    /// The color this motion is currently blended to, given the fill it is moving toward.
297    ///
298    /// What a retarget snapshots. A blend of two fills is a color and not a fill, so there is
299    /// nothing else it could be.
300    fn tint(&self, scheme: &Scheme, to: Fill) -> Color {
301        let Moving::Fill(departed) = &self.moving else {
302            return to.color(scheme);
303        };
304        let from = match departed {
305            Departed::Declared(fill) => fill.color(scheme),
306            Departed::Snapshot(color) => *color,
307        };
308        from.blend(to.color(scheme), self.progress.at())
309    }
310}

313/// concept of. It writes nothing.
314#[derive(Copy, Clone, Debug)]
315struct Channel {
316    from: f32,
317    to: f32,
318    progress: Progress,
319    within: Option<Sequence>,
320}

322/// Every running tween.
323///
324/// Held beside the tree rather than on the elements, because what is moving is a small set and
325/// almost never the tree: this phase walks what is running, and the loop can ask whether anything
326/// is (F9) without a pass over anything.
327#[derive(Default)]
328pub(crate) struct Aspen {
329    motions: HashMap<(Leaf, Property), Motioning>,
330    channels: HashMap<Tween, Channel>,
331    /// How many tweens are still running under each named group. An entry exists only while the
332    /// group has something in it, so a group that is over holds nothing and a name that is used
333    /// again starts a new one.
334    sequences: HashMap<Sequence, usize>,
335    /// Groups whose last member ended, waiting to be reported. Drained once a frame, so a group
336    /// emptied at the drain and one emptied by a tween finishing read the same way.
337    finished: Vec<Sequence>,
338}
339
340impl Aspen {
341    /// Counts one more tween into a group.
342    fn enroll(&mut self, within: Option<Sequence>) {
343        if let Some(sequence) = within {
344            *self.sequences.entry(sequence).or_default() += 1;
345        }
346    }
347
348    /// Takes one tween out of a group, however it ended, and notes the group if that was the last.
349    fn release(&mut self, within: Option<Sequence>) {
350        let Some(sequence) = within else {
351            return;
352        };
353        let Some(running) = self.sequences.get_mut(&sequence) else {
354            return;
355        };
356        *running -= 1;
357        if *running == 0 {
358            self.sequences.remove(&sequence);
359            self.finished.push(sequence);
360        }
361    }
362
363    /// Whether nothing is running, which is half of whether the loop owes a frame.
364    pub(crate) fn idle(&self) -> bool {
365        self.motions.is_empty() && self.channels.is_empty()
366    }
367
368    /// How many tweens are running.
369    fn live(&self) -> usize {
370        self.motions.len() + self.channels.len()
371    }
372
373    /// The motion moving `leaf`'s placement: where it came from, and how far it has come.
374    ///
375    /// Read by R2, once per axis. The `None` case is the whole tree on almost every frame, so it is
376    /// answered without hashing when nothing is moving at all.
377    pub(crate) fn location(&self, leaf: Leaf) -> Option<(&Departed<Location, Section>, f32)> {
378        let motioning = self.moving(leaf, Property::Location)?;
379        match &motioning.moving {
380            Moving::Location(departed) => Some((departed, motioning.progress.at())),
381            _ => None,
382        }
383    }
384
385    /// Every region a motion is moving: what it left, where it is going, and how far it has come.
386    ///
387    /// Read by R4, which is the one pass holding both this frame's extent and the offset the
388    /// destination is answered into. Collected rather than borrowed because applying one writes to
389    /// the tree, and the set is at most a handful of regions.
390    pub(crate) fn scrolling(&self) -> Vec<(Leaf, Position, ScrollTo, f32)> {
391        self.motions
392            .iter()
393            .filter_map(|((leaf, _), motioning)| match &motioning.moving {
394                Moving::Scroll { from, to } => Some((*leaf, *from, *to, motioning.progress.at())),
395                _ => None,
396            })
397            .collect()
398    }
399
400    /// The motion moving `leaf`'s fill, on the same terms. Read by extraction.
401    pub(crate) fn fill(&self, leaf: Leaf) -> Option<(&Departed<Fill, Color>, f32)> {
402        let motioning = self.moving(leaf, Property::Fill)?;
403        match &motioning.moving {
404            Moving::Fill(departed) => Some((departed, motioning.progress.at())),
405            _ => None,
406        }
407    }
408
409    fn moving(&self, leaf: Leaf, property: Property) -> Option<&Motioning> {
410        if self.motions.is_empty() {
411            return None;
412        }
413        self.motions.get(&(leaf, property))
414    }
415
416    /// Drops the motion on one property, reporting whether one was running.
417    ///
418    /// F8: this is what a direct write does before it lands, so no property ever reaches its
419    /// applying phase with both a pending write and a running tween.
420    pub(crate) fn cancel(&mut self, leaf: Leaf, property: Property) -> bool {
421        let Some(motioning) = self.motions.remove(&(leaf, property)) else {
422            return false;
423        };
424        self.release(motioning.within);
425        true
426    }
427
428    /// Drops everything running on elements that have gone.
429    pub(crate) fn wither(&mut self, gone: &[Leaf]) {
430        if self.motions.is_empty() {
431            return;
432        }
433        for leaf in gone {
434            for property in Property::ALL {
435                if let Some(motioning) = self.motions.remove(&(*leaf, property)) {
436                    self.release(motioning.within);
437                }
438            }
439        }
440    }
441
442    pub(crate) fn channel(&mut self, tween: Tween, from: f32, to: f32, timing: Timing) {
443        let within = timing.sequence();
444        self.enroll(within);
445        if let Some(replaced) = self.channels.insert(
446            tween,
447            Channel {
448                from,
449                to,
450                progress: Progress::new(timing),
451                within,
452            },
453        ) {
454            // A name is never reused, so this cannot happen from an app -- but the count is the
455            // group's only record and it has to survive anything that takes a member out.
456            self.release(replaced.within);
457        }
458    }
459}

461/// Starts a motion, replacing whatever was moving that property, and reports whether it applied.
462///
463/// The target is written to the element here rather than when the motion ends, so what the element
464/// declares is already where it is going. What the motion carries is what the element no longer
465/// holds: the placement or the role it left, or -- for a value written back over its own
466/// declaration -- both of its ends.
467pub(crate) fn animate(
468    grove: &mut Grove,
469    leaf: Leaf,
470    motion: Motion,
471    timing: Timing,
472    tween: Tween,
473) -> bool {
474    let scheme = grove.scheme;
475    let Grove {
476        tree,
477        aspen,
478        coasting,
479        ..
480    } = grove;
481    let (property, moving) = match motion {
482        Motion::Location(to) => {
483            let departed = match aspen.motions.contains_key(&(leaf, Property::Location)) {
484                // Where the element is now, which is a box between two placements rather than a
485                // placement of its own.
486                true => Departed::Snapshot(tree.placed(leaf)),
487                false => Departed::Declared(tree.location(leaf).cloned().unwrap_or_default()),
488            };
489            tree.set_location(leaf, to);
490            (Property::Location, Moving::Location(departed))
491        }
492        Motion::Opacity(to) => {
493            // The blend is written back over the declaration every frame, so what the element
494            // declares *is* where it currently is -- a retarget needs nothing else.
495            let from = tree.opacity(leaf).0;
496            (
497                Property::Opacity,
498                Moving::Opacity {
499                    from,
500                    to: to.clamp(0.0, 1.0),
501                },
502            )
503        }
504        // Two ways to say where a fill is going, one property and one applier. The value is
505        // normalised the moment it arrives, so nothing past this point knows which was written.
506        Motion::Color(to) => match filling(tree, aspen, &scheme, leaf, Fill::Literal(to)) {
507            Some(moving) => (Property::Fill, moving),
508            None => return false,
509        },
510        Motion::Palette(to) => match filling(tree, aspen, &scheme, leaf, Fill::Role(to)) {
511            Some(moving) => (Property::Fill, moving),
512            None => return false,
513        },
514        Motion::Polygon(to) => {
515            // The blend is written back over the declaration every frame, so what the element
516            // declares *is* the shape it currently is -- a retarget needs nothing else, exactly as
517            // an opacity does not.
518            let Some(from) = tree.shape(leaf) else {
519                return false;
520            };
521            (Property::Shape, Moving::Shape { from, to })
522        }
523        Motion::Scroll(to) => {
524            // Where the region is now, which is what the last frame's R4 settled it at. A retarget
525            // needs nothing else: an offset is already a number, so there is no departed
526            // declaration a snapshot could be a worse answer than.
527            let from = tree.offset(leaf);
528            // A motion is a write, and the region cannot be moving under two of them.
529            coasting.stop(leaf);
530            (Property::Scroll, Moving::Scroll { from, to })
531        }
532    };
533    let within = timing.sequence();
534    aspen.enroll(within);
535    if let Some(replaced) = aspen.motions.insert(
536        (leaf, property),
537        Motioning {
538            moving,
539            progress: Progress::new(timing),
540            tween,
541            within,
542        },
543    ) {
544        // One writer per property: a second motion replaces the first, and the first is out of
545        // whatever group it was counted into whether or not the second joined the same one.
546        aspen.release(replaced.within);
547    }
548    true
549}

551/// Ends whatever `tween` names before it has run out, on the end it was going to, and reports
552/// whether anything was running.
553///
554/// A motion is left on its target: that is what the element was told to be when the motion started,
555/// and the duration was only how long it was to take getting there. Ending it anywhere else is a
556/// write to that property, which is already how a motion is cancelled (F8) -- nothing here
557/// synthesizes a declaration out of a blend part way along, which is the same reason a retarget
558/// carries a snapshot rather than writing one back.
559///
560/// `reported` is the difference between the two verbs. Reported, this is an arrival and reads
561/// exactly as the tween's own last frame would have; silent, a chain waiting on the name never runs.
562/// Either way the group counting it hears the only thing a group is about -- that one fewer thing is
563/// running under it.
564pub(crate) fn stop(grove: &mut Grove, tween: Tween, reported: bool) -> bool {
565    let Grove {
566        aspen,
567        tree,
568        sought,
569        drift,
570        ..
571    } = grove;
572    if let Some(channel) = aspen.channels.remove(&tween) {
573        aspen.release(channel.within);
574        if reported {
575            // Its end value and its finish together, which is what its own last frame would have
576            // reported -- so there is no end value to infer from an absence either way it ended.
577            drift.tweens.insert(tween, channel.to);
578            drift.finished.insert(tween);
579        }
580        debug!(tween = tween.0, reported, "channel stopped");
581        return true;
582    }
583    // A name is never handed out twice, so at most one motion answers to it. Walked rather than
584    // indexed, because what is moving is a handful and a second map would have to be kept in step
585    // with this one through every way a motion ends.
586    let mut stopped = None;
587    aspen.motions.retain(|(leaf, _), motioning| {
588        if motioning.tween != tween {
589            return true;
590        }
591        stopped = Some((*leaf, motioning.moving.clone(), motioning.within));
592        false
593    });
594    let Some((leaf, moving, within)) = stopped else {
595        return false;
596    };
597    aspen.release(within);
598    land(tree, sought, leaf, &moving);
599    if reported {
600        drift.tweens.insert(tween, 1.0);
601        drift.finished.insert(tween);
602        drift.landed.insert(leaf);
603    }
604    debug!(leaf = leaf.id(), tween = tween.0, reported, "tween stopped");
605    true
606}

608/// Puts an element where its motion was taking it, for both ways a motion ends on its target:
609/// running out, and being stopped.
610///
611/// Nothing to state where the element's own declaration is the target -- a placement and a fill are
612/// written when the motion starts, so arriving is a removal. What is blended back over its
613/// declaration holds where the motion reached rather than where it was going, and an offset is not a
614/// declaration at all, so those are written out here. A region's is written as though it had been
615/// written directly, which is what makes the frame after a landing identical to the one it landed in.
616fn land(tree: &mut Tree, sought: &mut Vec<(Leaf, ScrollTo)>, leaf: Leaf, moving: &Moving) {
617    match moving {
618        Moving::Location(_) | Moving::Fill(_) => {}
619        Moving::Opacity { to, .. } => tree.set_opacity(leaf, *to),
620        Moving::Shape { to, .. } => {
621            tree.set_shape(leaf, *to);
622        }
623        Moving::Scroll { to, .. } => sought.push((leaf, *to)),
624    }
625}
626
627/// Writes a fill target to the element and hands back what it left, or `None` if there is no fill
628/// on it to move.
629///
630/// A retarget snapshots the color, because a blend of two fills is a color and not a fill. Otherwise
631/// the endpoint is the fill the element declared, which resolves against the scheme every frame
632/// exactly as the target does -- so a role at either end follows a repaint and a literal at either
633/// end does not, which is the whole of what the two mean.
634fn filling(
635    tree: &mut Tree,
636    aspen: &Aspen,
637    scheme: &Scheme,
638    leaf: Leaf,
639    to: Fill,
640) -> Option<Moving> {
641    let declared = tree.fill(leaf)?;
642    let departed = match aspen.motions.get(&(leaf, Property::Fill)) {
643        Some(motioning) => Departed::Snapshot(motioning.tint(scheme, declared)),
644        None => Departed::Declared(declared),
645    };
646    tree.set_fill(leaf, to);
647    Some(Moving::Fill(departed))
648}

650/// Step 5. Every live tween advances against the one clock.
651///
652/// The clock is the frame's, sampled once at step 1, so two tweens started together stay together
653/// and a test that moves it by hand is exact.
654pub(crate) fn run(grove: &mut Grove) {
655    let _step = trace_span!("animate", tweens = grove.aspen.live()).entered();
656    let delta = grove.clock.delta();
657    channels(grove, delta);
658    motions(grove, delta);
659    sequences(grove);
660}
661
662/// The channels: a value each, reported outward and written nowhere.
663fn channels(grove: &mut Grove, delta: Duration) {
664    let Grove { aspen, drift, .. } = grove;
665    let mut ended = Vec::new();
666    aspen.channels.retain(|tween, channel| {
667        let at = channel.progress.advance(delta);
668        drift
669            .tweens
670            .insert(*tween, blend(channel.from, channel.to, at));
671        if !channel.progress.done() {
672            return true;
673        }
674        // The frame it ends reports its end value and its finish together, so an app reading one
675        // never has to infer the other from an absence.
676        drift.finished.insert(*tween);
677        debug!(tween = tween.0, "tween finished");
678        ended.push(channel.within);
679        false
680    });
681    for within in ended {
682        aspen.release(within);
683    }
684}
685
686/// The motions: advanced here, and applied by whichever phase owns what they are moving.
687fn motions(grove: &mut Grove, delta: Duration) {
688    let Grove {
689        aspen,
690        tree,
691        drift,
692        sought,
693        ..
694    } = grove;
695    let mut ended = Vec::new();
696    aspen.motions.retain(|(leaf, _), motioning| {
697        let at = motioning.progress.advance(delta);
698        // How far it has come, for the app holding its name. The eased progress and not the fraction
699        // of the duration, because what a motion is a fraction of the way through is what it looks
700        // like, and the two differ under every shape but `Linear`.
701        drift.tweens.insert(motioning.tween, at);
702        if let Moving::Opacity { from, to } = motioning.moving {
703            tree.set_opacity(*leaf, blend(from, to, at));
704        }
705        if let Moving::Shape { from, to } = motioning.moving {
706            tree.set_shape(*leaf, from.blend(to, at));
707        }
708        if !motioning.progress.done() {
709            return true;
710        }
711        // What the element declares is already the target, so ending is a removal: the blend at the
712        // end equals the plain reading of the declaration. What is not declared on the element is
713        // written out here, so the frame after a landing is identical to the one it landed in.
714        land(tree, sought, *leaf, &motioning.moving);
715        // Two reports for one arrival, and they answer different questions: the element settled,
716        // and this motion is the one that ended.
717        drift.landed.insert(*leaf);
718        drift.finished.insert(motioning.tween);
719        debug!(leaf = leaf.id(), tween = motioning.tween.0, "tween landed");
720        ended.push(motioning.within);
721        false
722    });
723    for within in ended {
724        aspen.release(within);
725    }
726}

728/// The groups that emptied, however their last member ended.
729///
730/// Drained once, here, rather than reported where each member ended: a group is over when nothing
731/// is running under it, and that can be settled by a landing, by a direct write cancelling the last
732/// one, or by the element carrying it being taken down. One place to report it is what keeps those
733/// three the same fact.
734fn sequences(grove: &mut Grove) {
735    let Grove { aspen, drift, .. } = grove;
736    for sequence in aspen.finished.drain(..) {
737        drift.sequences.insert(sequence);
738        debug!(sequence = sequence.0, "sequence finished");
739    }
740}

742/// One number a fraction of the way to another.
743///
744/// Exact at both ends rather than merely close. A motion lands *on* its target, and an arithmetic
745/// form that arrived a rounding error short of one would put every landing a fraction out and leave
746/// every arrival needing a correction after it. The two comparisons are against the values
747/// [`Ease`] returns exactly at the ends of a motion, and against nothing else -- a shape that
748/// overshoots is left to overshoot.
749pub(crate) fn blend(from: f32, to: f32, at: f32) -> f32 {
750    if at == 0.0 {
751        return from;
752    }
753    if at == 1.0 {
754        return to;
755    }
756    from + (to - from) * at
757}
