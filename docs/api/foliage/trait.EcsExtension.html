Expand description

The shared vocabulary for building and changing a tree, implemented for Tree, World and DeferredWorld so the same calls work from a system, an observer, a component hook, or startup.

leaf and branch spawn; write_to changes a live value; animate and sequence move things; react and subscribe respond.

fn refire<C>(&mut self, entity: Entity)
where C: Refire,

Re-inserts entity’s current value(s) of C so any just-registered observer fires with real data – the fire-once half of EcsExtension::react. Internal plumbing; authors use react.

Provided Methods§

fn trigger_targets<E>(&mut self, e: E, targets: impl IntoTargets)
where E: TargetedEvent, <E as Event>::Trigger<'a>: for<'a> Default,

Same as EcsExtension::send_to — kept under the pre-0.19 name so the many composite-internal call sites read the same as they always have.

fn on_asset<AFN>(&mut self, entity: Entity, key: u128, afn: AFN)
where AFN: FnMut(&mut Commands<'_, '_>, Entity, Vec<u8>) + Send + Sync + 'static, Self: Sized,

Runs afn on entity once the asset key names has arrived, with its bytes – the asset counterpart to on_click. Marks the wait and registers the handler in one call, so the key can’t disagree between them.

On native a Bytes asset is already there and this fires almost immediately; on wasm it fires whenever the fetch resolves. Either way anything that needs the bytes belongs in afn rather than after the spawn.

fn leaf<S>(&mut self, spec: S) -> Entity
where S: Sprout, Self: Sized,

Grows spec as a top-level entity – no parent, the EcsExtension::branch counterpart for roots (a screen, a one-off widget): let root = tree.leaf(Icon::new(0).elevate(..));

fn branch<S>(&mut self, parent: Entity, spec: S) -> Entity
where S: Sprout, Self: Sized,

Grows spec as a child of parent – parent filled by the required argument, so a child can’t be spawned orphaned by forgetting a chained call. THE way to build a composite’s structure, in Sprout::build and one-off screens alike: let icon = tree.branch(this, Icon::new(0).elevate(..));

fn react<C, M>(&mut self, entity: Entity, observer: impl IntoEntityObserver<M>)
where C: Component + Clone,

Registers observer – a plain bevy entity-observer watching Trigger<Insert, C>, full SystemParam freedom – on entity, then re-fires it once with the current value so initial state and every later write_to run the SAME code path. This is the one door for everything data-dependent in a composite: values AND structure (a dropdown’s option rows, a hand’s cards). What the body does – respawn, pool, patch – is entirely the author’s policy. The _ stands in for the observer’s inferred marker: tree.react::<TextValue, _>(this, ..).

fn react_any<CS, M>( &mut self, entity: Entity, observer: impl IntoEntityObserver<M>, )
where CS: Refire,

EcsExtension::react over a component SET: the observer watches Trigger<Insert, (A, B)> and fires when ANY member is written – one registration, one body, for state derived from several inputs (Button’s style + engagement). The build-time re-fire inserts only the first present member: one fire is enough because reaction bodies read the current state of everything they depend on.

fn forward<C>(&mut self, source: Entity, target: Entity)
where C: Component + Clone,

EcsExtension::react specialized to the pure-copy case: source’s C is copied to target verbatim, now and on every write. Anything that is NOT a pure copy (a text whose width also depends on the value) stays an explicit react – the boundary is visible on purpose.

fn graft(&mut self, entity: Entity) -> Graft<'_, Self>
where Self: Sized,

Grafts further behavior (on_click, animate, extra components) onto an already-spawned entity right next to where it was created, instead of in a separate pass elsewhere: tree.graft(e).on_click(...).animate(...);
